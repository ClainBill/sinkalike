# Sink Alike website

The home of the Sink Alike podcast: every episode with a full transcript, a movie archive with our takes and pull quotes, quote search, comments and polls, host bios, and our sponsor.

**Live at https://sink-alike.wcgill.com** (moving to sinkalike.com once it's bought; see [Moving to sinkalike.com](#moving-to-sinkalikecom)).

- **Static pages** built with [Astro](https://astro.build): fast, cheap, and good for SEO.
- **A small Cloudflare Worker** handles comments, polls and sign-in, backed by a **D1** (SQLite) database.
- **Audio** streams straight from our podcast host (Spotify for Creators), so the site never pays for audio bandwidth.

**Running cost:** about £8–10 a year for the domain. Everything else fits in free tiers (Cloudflare Workers + D1, Turnstile, GitHub Actions, Resend). The one exception is SMS login codes, which Twilio charges for per message. See [Sign-in](#sign-in).

## Everyday workflow: a new episode

1. **Publish on Spotify for Creators** as usual.
2. **The site picks it up automatically.** A GitHub Action checks the RSS feed every morning. You can also run it manually from Actions → *Sync episodes from RSS* → *Run workflow*, or run `npm run sync` locally. A new episode appears on the site straight away, with a stub file at `src/content/episodes/<n>-<title>.md`.
3. **Transcribe.** Export each person's track **from the final edit**, so every track matches the published episode's length and cuts. Then run:
   ```sh
   npm run transcribe -- 2 --track adam=~/Desktop/ep2-adam.wav --track william=~/Desktop/ep2-william.wav
   ```
   Speaker names come from the separate tracks, so they're exact. The script warns if a track's length doesn't match the published episode. Skim the result for misheard names and add repeat offenders to `scripts/vocab.txt`.

   No tracks? Run `npm run transcribe -- 2 --mixed` instead. It transcribes the published episode and **detects who's speaking automatically** by recognising each voice. It names the voices from cues like "I'm your host, Adam…" or "William, what did you think?". Expect the odd wrong line, mostly in fast back-and-forth. Check the summary it prints; if the names come out swapped, re-run with `--anchor adam=12` (any second where Adam is talking). Re-runs take under a minute because the transcription is cached.
4. **Add the movie the episode is about:** `npm run add-movie -- "Speed Racer" 2008`. This downloads the poster and details from TMDB. Then list the movie slug under `movies:` in the episode file.
5. **Pick up every other movie you mentioned:** `npm run find-movies` lists what it heard, and `npm run find-movies -- --write` adds them. Each new movie gets its own page and a card under "Mentioned on the show", with the line where you said it. Titles are matched against TMDB's full movie list, and everyday-word titles ("Up", "Cars") only count when they're clearly said as a title. If it adds something wrong:
   - **On the site:** sign in as a host, then press **Remove from list** on the card. It takes effect instantly, and you can Restore it the same way.
   - **Permanently:** set `hidden: true` in `src/content/movies/<slug>.md`, or add its TMDB id to `scripts/movie-ignore.txt` so it's never added again.
6. **Write the fun bits:**
   - In `src/content/movies/<slug>.md`: **Our take** (the body), `verdicts` (a rating out of 10 and a one-liner each), and `quotes`. For a pull quote, find the line in quote search, copy its timestamp in seconds from the link (`?t=612`), and add `{ episode: 2-some-movie, start: 612 }`.
   - In the episode file: `chapters`, a `poll`, and `guests`.
7. **Publish:** `npm run deploy`. It builds and uploads in about a minute. Once the repo is connected to Cloudflare (step 5 of the first deploy), pushing to `main` does this automatically.

### Where things live

| What | File |
| --- | --- |
| Show name, links, sponsor copy and **discount code** | `src/site.config.ts` |
| Host bios, photos, favourite films and links | `src/content/people/adam.md`, `william.md` (put photos in `src/content/people/photos/` and set `photo: ./photos/adam.jpg`) |
| Episode extras (participants, guests, movies, chapters, poll) | `src/content/episodes/*.md` |
| Episode title, description, date, audio | `src/data/feed.json`. **Don't edit it:** it's regenerated from RSS, so change these on Spotify for Creators. |
| Transcripts | `src/content/transcripts/*.json` (generated; hand-fixes are fine) |
| Movies | `src/content/movies/*.md` + `posters/`. Ones with `auto: true` were added by find-movies. |
| Where each movie was mentioned | `src/data/mentions.json` (generated by `npm run find-movies -- --write`) |
| Movies find-movies should never add | `scripts/movie-ignore.txt` |
| Host colours | `--person-adam` / `--person-william` in `src/styles/global.css` |
| Logo | The wordmark in `src/components/Header.astro` and `Footer.astro`; the favicon is `public/favicon.svg` (run `node scripts/make-icons.mjs` after changing it) |

## Local development

Requirements: Node 22.12+ and, for transcription, Python 3 on an Apple Silicon Mac.

```sh
npm install
cp .dev.vars.example .dev.vars     # then fill in two random strings (openssl rand -hex 32)
npm run db:migrate:local           # creates the local SQLite database
npm run dev                        # http://localhost:4321

# one-time, for transcription
python3 -m venv .venv && .venv/bin/pip install mlx-whisper speechbrain scikit-learn
```

In local dev, **login codes are printed in the terminal** instead of being emailed or texted, and the spam check uses Cloudflare's always-pass test keys. Host/moderator rights go to the addresses in `ADMINS`.

`npm run check` type-checks everything. `npm run preview` builds and serves the production bundle locally.

**"The file does not exist at …/node_modules/.vite/deps…":** a build or check ran while the dev server was running and replaced Vite's shared cache. Stop the dev server, run `rm -rf node_modules/.vite`, start it again, and hard-refresh the browser (⌘⇧R).

## Hosting (already set up)

The site runs on Cloudflare Workers in the wcgill.com account:
- **Worker:** `sinkalike`, at https://sink-alike.wcgill.com
- **Database:** D1 `sinkalike`, with all migrations applied
- **Secrets:** `BETTER_AUTH_SECRET`, `IP_HASH_SALT` and `TURNSTILE_SECRET_KEY` (Turnstile widget "Sink Alike", valid for sink-alike.wcgill.com and sinkalike.com)

`npm run deploy` publishes from your Mac. New database migrations go in `migrations/`; apply them with `npm run db:migrate` before deploying.

**Code:** https://github.com/ClainBill/sinkalike (private). A GitHub Action checks the RSS feed daily and commits new episodes.

**Auto-deploy on push (one-time, about 2 minutes):** in the Cloudflare dashboard, open *Workers & Pages → sinkalike → Settings → Build → Connect*, pick the `ClainBill/sinkalike` repo and branch `main`, and set build command `npm run build` and deploy command `npx wrangler deploy`. After that, every push (including the daily RSS commits) goes live automatically. Secrets stay on the Worker, so the build doesn't need them.

**Sign-in isn't switched on in production yet.** Anonymous comments and votes work, but hosts can't log in to moderate or remove movies until at least one provider is set up. Google is the quickest (see [Sign-in](#sign-in)).

### Moving to sinkalike.com

1. Buy the domain in Cloudflare.
2. In `wrangler.jsonc`, add `{ "pattern": "sinkalike.com", "custom_domain": true }` under `routes` and set `BETTER_AUTH_URL` to `https://sinkalike.com`.
3. In `astro.config.mjs`, set `site` to `https://sinkalike.com`.
4. Run `npm run deploy`. Optionally add a Redirect Rule from sink-alike.wcgill.com to sinkalike.com.

## Setting up from scratch (reference)

1. **Domain.** Any domain on the Cloudflare account works (currently sink-alike.wcgill.com). `sinkalike.com` costs about $10/yr through *Domain Registration*.
2. **Push this folder to a GitHub repo.** It can be private.
3. **Create the database:**
   ```sh
   npx wrangler login
   npx wrangler d1 create sinkalike          # copy the database_id into wrangler.jsonc (done)
   npm run db:migrate                        # creates the tables in production
   ```
4. **Spam protection.** In the dashboard, open *Turnstile → Add widget* in Managed mode (done: "Sink Alike"). Put the **site key** in `src/site.config.ts` (it's public), then store the secret:
   ```sh
   npx wrangler secret put TURNSTILE_SECRET_KEY
   npx wrangler secret put BETTER_AUTH_SECRET   # paste: openssl rand -hex 32
   npx wrangler secret put IP_HASH_SALT         # paste: openssl rand -hex 32
   ```
5. **Connect the repo to Cloudflare.** Go to *Workers & Pages → Create → Import a repository*, pick the repo, and set build command `npm run build` and deploy command `npx wrangler deploy`. Every push to `main` then deploys.
6. **Attach the domain.** Uncomment the `routes` entry in `wrangler.jsonc` and push. To make `www.sinkalike.com` work too, add a Redirect Rule from `www` to the bare domain.
7. **Analytics (optional).** In *Web Analytics*, add the site. It's cookieless and needs no code.
8. **Email.** *Email → Email Routing* forwards `hello@sinkalike.com` to your Gmail for free.

### Sign-in

Anonymous commenting and voting always work. Each sign-in method switches on once its credentials exist:

| Method | Set up | Cost |
| --- | --- | --- |
| **Google** | [Google Cloud console](https://console.cloud.google.com/apis/credentials): create an OAuth client ID (Web). Redirect URIs: `https://sinkalike.com/api/auth/callback/google` and `http://localhost:4321/api/auth/callback/google`. Then run `wrangler secret put GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET`. | Free |
| **Email code** | [Resend](https://resend.com): add and verify `sinkalike.com` (it gives you DNS records to add in Cloudflare), then run `wrangler secret put RESEND_API_KEY`. | Free up to 3,000 emails/month |
| **Phone code** | [Twilio](https://www.twilio.com): buy a number, then run `wrangler secret put` for `TWILIO_ACCOUNT_SID`, `TWILIO_AUTH_TOKEN` and `TWILIO_FROM`. **Set a spending limit** in Twilio. | About $0.01–0.05 per text, depending on country |

Code requests are rate-limited (3 per 5 minutes) and protected by Turnstile, which blocks the "SMS pumping" abuse that runs up phone bills.

### Moderation

Hosts sign in with an address listed in `ADMINS` (in `wrangler.jsonc`). They get a **Host** badge, can hide or delete any comment, and have a queue at `/admin/`. Anonymous comments that contain links are held for approval. Everyone else is rate-limited.

## How it fits together

```
src/
  site.config.ts          show-wide settings, sponsor, listen links
  content.config.ts       content schemas (validated at build time)
  data/feed.json          RSS snapshot (generated)
  content/                episodes, transcripts, movies, people
  pages/                  routes; pages/api/* run on the Worker
  components/islands/     interactive Preact components (player, search, comments, polls, sign-in)
  lib/player.ts           shared audio-player state (the player persists across page changes)
  lib/server/             auth (Better Auth), comments/polls helpers
migrations/               D1 schema
scripts/                  sync-rss, transcribe, add-movie, icons
```

- **Pages are static.** Only `/api/*`, `/login/`, `/account/` and `/admin/` run on the Worker. The quote-search index (`/quotes/index.json`) is built at deploy time and searched in the browser with MiniSearch.
- **Deep links:** `/episodes/<slug>/?t=612` opens the episode cued to 10:12 and highlights that transcript line. Quote search and pull quotes use this.
- **Scaling note:** quote search downloads every transcript line once (roughly 25 KB gzipped per episode). That's fine for a couple of hundred episodes. Beyond that, switch to a sharded index such as Pagefind.
